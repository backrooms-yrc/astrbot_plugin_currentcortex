## 🚀 はじめに

### 1. インストール

**方法1：プラグインマーケット（推奨）** — AstrBot 管理パネルで `astrbot_plugin_currentcortex` を検索してインストール。

**方法2：手動クローン：**

```bash
cd AstrBot/data/plugins
git clone https://github.com/backrooms-yrc/astrbot_plugin_currentcortex.git
```

### 2. API キー設定 (必須)

> 🔐 **LeiZ API 認証**：最新バージョンより、**すべてのエンドポイント（無料エンドポイントを含む）で API キーが必須**となりました。リクエストヘッダーは `x-api-key: <API-Key>` です。

#### ステップ1：API キーを取得

**LeiZ API 公式サイト**へ 👉 [https://api.bileizhen.top](https://api.bileizhen.top)

登録／ログイン後、「コンソール / API Keys」ページでキーを作成・コピーしてください（これが `x-api-key` の値になります）。キーは LeiZ の全エンドポイント（Pixiv / Hitokoto / 天気 / 男の娘 / 網易雲）で共通で、1つあれば十分です。

> 💡 具体的な取得場所はサイトのレイアウトに依存します（例：「コンソール → API Keys / トークン管理」）。公式サイトの手順が優先されます。

#### ステップ2：プラグイン設定に入力

AstrBot 管理パネル → プラグイン管理 → 本プラグイン → 設定 を開き、取得したキーを **`leiz_api_key`** フィールドに貼り付けて保存し、プラグインを再読み込みしてください。

キー未設定の場合、Pixiv / Hitokoto / 天気 / 男の娘 / リクエストなど LeiZ 系コマンドはすべて無効になり、実行すると設定を案内するメッセージが返ります。

> ⚠️ **本プラグインは LeiZ API を利用したコミュニティ（サードパーティ）プラグインであり、LeiZ API 公式とは独立しています**。API キーの登録・取得、課金、クォータ、上流障害については [LeiZ API 公式サイト](https://api.bileizhen.top) と公式チャンネルにお問い合わせください。本プラグインのグループはプラグイン自体の問題のみ扱います。

> **旧バージョンからの移行**：v1.3.x 以前の `femboy_api_key` は統一された `leiz_api_key` に統合されました。新フィールドが空で旧フィールドが残っている場合、プラグインは自動でそれを統一キーとして使用し移行を促します。早めに `leiz_api_key` へ移してください。

### 3. 依存関係のインストール

```bash
pip install aiohttp>=3.8.0
pip install websockets>=10.0   # DG-LAB 機能のみ必要
```

### 動作環境

- **AstrBot** >= 4.15（< 5。`EventMessageType`、ハンドラー `priority`、`ProviderRequest` など比較的新しい API を使用）
- **Python** >= 3.10
- **aiohttp** >= 3.8.0
- **websockets** >= 10.0（DG-LAB 機能に必須）
- **ffmpeg**（網易雲ボイス機能に必要。システム PATH 上にあること）

### 1. Pixiv ランダム画像 (`/pixiv`)

LeiZ API 経由でランダムな Pixiv 作品を取得します。多彩な絞り込み・検索に対応。

#### 基本コマンド

| コマンド | 説明 |
| --- | --- |
| `/pixiv` | ランダム画像を1枚取得（デフォルトパラメータ） |
| `/pixiv help` | ヘルプ表示 |

#### パラメータ（`key:value` 形式、スペース区切り、自由に組み合わせ可能）

| パラメータ | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `r18:` | int | 0 | R18 モード：`0`=全年齢、`1`=R18 のみ、`2`=ミックス |
| `num:` | int | 1 | 取得枚数（1-20） |
| `size:` | string | regular | 画像サイズ：`original`/`regular`/`small`/`thumb`/`mini` |
| `tag:` | string | — | タグ絞り込み。タグ内の `\|` は **OR**、複数 `tag:` の指定は **AND** |
| `keyword:` | string | — | タイトル／作者／タグのあいまい検索 |
| `uid:` | int | — | 作者 UID の指定 |
| `ratio:` | string | — | アスペクト比フィルタ（例：`gt1.2lt1.8`） |
| `excludeAI:` | bool | false | AI 生成作品を除外 |

#### 省略記法

| 省略形 | 同義 |
| --- | --- |
| `r18` | `r18:1` |
| `mixed` | `r18:2` |
| `safe` / `sfw` | `r18:0` |

#### 使用例

```text
# 基本系
/pixiv                          # ランダムな全年齢画像
/pixiv r18:1                    # ランダムな R18 画像
/pixiv num:5                    # 一度に5枚取得

# タグ・キーワード検索
/pixiv tag:白丝 num:3           # 白絹タグの画像を3枚
/pixiv keyword:初音ミク num:5   # 初音ミク関連を検索
/pixiv tag:萝莉 excludeAI:true  # AI 作品を除外した萝莉タグ
/pixiv uid:123456 num:3         # 指定作者の作品

# 組み合わせ絞り込み
/pixiv r18:2 tag:白丝 keyword:初音ミク num:3 size:original

# 省略記法
/pixiv r18                      # r18:1 と同義
/pixiv mixed                    # r18:2 と同義
```

#### 返信例

```text
📷 [1/3]
🎨 冬の午後
👤 作者：SampleArtist
🔗 https://www.pixiv.net/artworks/12345678
🏷️ タグ：オリジナル / 女の子 / 冬 / 雪
📐 サイズ：1920×1080
[画像]
```

> 💡 **ランダムと検索の切替**：`tag`/`keyword`/`uid`/`ratio`/`excludeAI` などのフィルタがない場合は GET ランダムエンドポイント（毎回結果が変わる）、いずれかのフィルタがあると自動で POST 検索エンドポイントに切り替わります。

### 2. メディア解析 (`/xhs` `/bilibili` `/douyin`)

小紅書・Bilibili・Douyin・Weibo のリンクからプラットフォームを自動判別し、透かしなし画像／動画情報を返します。

#### 基本コマンド

| コマンド | 説明 |
| --- | --- |
| `/解析 <リンク>` | プラットフォーム自動判別して解析。**1 通に複数リンクがある場合は順番に解析（最大 5 件）** |
| `/xhs <リンク>`（`/小红书`） | 小紅書解析 |
| `/bilibili <リンク>`（`/B站` `/b站`） | Bilibili 動画解析 |
| `/douyin <リンク>`（`/抖音`） | Douyin 動画解析 |
| `/weibo <リンク>`（`/微博`） | Weibo 投稿解析 |
| `/解析 help` | ヘルプ表示 |

### 対応リンク形式

| プラットフォーム | 対応形式 |
| --- | --- |
| 小紅書 | `xiaohongshu.com/explore/xxx`、`xhslink.com/xxx`（短縮リンク） |
| Bilibili | `bilibili.com/video/BVxxx`、`b23.tv/xxx`（短縮リンク）、`avxxx` |
| Douyin | `douyin.com/video/xxx`、`v.douyin.com/xxx`（短縮リンク） |
| Weibo | `weibo.com/<数字>/xxx`、`m.weibo.cn/detail/xxx`、`weibo.cn/status/xxx`、`t.cn/xxx`（短縮リンク） |

### 使用例

```text
/解析 https://www.xiaohongshu.com/explore/abc123
/解析 https://b23.tv/xxxx https://v.douyin.com/yyyy   # バッチ：1 通で複数リンクを順次解析
/xhs https://xhslink.com/xxxx
/bilibili https://www.bilibili.com/video/BV1xx411c7mD
/douyin https://v.douyin.com/xxxx
/weibo https://m.weibo.cn/detail/xxxxx
```

### 取得できる情報

- **小紅書**：タイトル、作者、いいね数、紹介文、透かしなしの高解像度画像、動画リンク（あれば）
- **Bilibili**：タイトル、投稿者、長さ、再生・いいね数、カバー、分割（P）情報、動画ダウンロードリンク（あれば）
- **Douyin**：タイトル、作者、いいね／コメント／シェア数、透かしなし動画リンク
- **Weibo**：本文、作者、転載／コメント／いいね数、画像（最大9枚）、動画リンク（あれば）

### 解析拡張

- **失敗原因の分級ヒント**：解析失敗時に生の例外テキストを垂れ流さず、原因別（リンク期限切れ・削除/非公開・プラットフォームのアンチスクレイピング・タイムアウト・形式不明など）に分類して提示し、リンク起因かネットワーク起因かを判別しやすくします。
- **結果キャッシュ**：同一リンクは有効期間内（デフォルト10分、`media_parse_cache_ttl` で調整）なら前回の解析結果をそのまま返し、対象プラットフォームへのリクエスト頻度とアンチスクレイピング／IP Ban の発生率を下げます。成功結果のみキャッシュし、失敗は即時リトライします。
- **グループ横断メモリ連動**：グループ横断メモリ有効時、解析成功は `media` タグで「誰が何を解析したか」として記録され、その後の会話で「さっきのあの動画」を自然に参照できます。

| 設定項目 | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `media_parse_cache_enable` | bool | true | 解析結果キャッシュの有効化 |
| `media_parse_cache_ttl` | int | 600 | キャッシュ有効期間（秒）。ダウンロード／再生リンク自体に期限があるため長くしすぎないこと |

> ⚠️ リンクが公開アクセス可能であることを確認してください。プラットフォーム側のアンチスクレイピングにより解析に失敗することがあります。ダウンロードリンクは個人の学習用であり、各プラットフォームの規約を守ってご利用ください。

### 3. 網易雲音楽 (`/music`)

LeiZ API 経由で楽曲のリクエスト・検索・再生リンク取得が可能。**網易雲**と**酷狗**のデュアル音源に、網易雲優先・失敗時酷狗へフォールバックする `auto` ルーティングを提供します。

#### 音源切替 (`/音源`)

| コマンド | 説明 |
| --- | --- |
| `/音源` | 現在の音源＋選択肢を表示 |
| `/音源 auto` | **デフォルト**。網易雲優先。VIP／権利なし／タイムアウト時に自動で酷狗へ切り替え |
| `/音源 网易云` | 網易雲のみ |
| `/音源 酷狗` | 酷狗のみ |

音源は**会話（グループ／DM）ごとに記憶**され、互いに影響しません。再起動するとデフォルト（`music_default_source`、初期値 auto）に戻ります。

#### 基本コマンド

| コマンド | 説明 |
| --- | --- |
| `/music <曲名>`（`/音乐`） | リクエスト（検索して1曲目の詳細を返す） |
| `/music direct <曲名>`（`/音乐 直接`） | トランスコード済みボイスのみ返す |
| `/点歌 <曲名>` | ショートカット。`/音乐 直接` と同等、ボイスのみ |
| `/music file <曲名>`（`/音乐 文件`） | トランスコード前の元の音楽ファイルを返す |
| `/music id:<楽曲ID>` | ID で詳細を取得 |
| `/music search <キーワード>` | 楽曲リストを検索 |
| `/music help` | ヘルプ表示 |

#### 使用例

```text
/music 孤勇者              # リクエスト
/music 周杰伦 晴天         # 「周杰伦 晴天」を検索
/music direct 孤勇者       # ボイスのみ
/点歌 孤勇者               # ショートカット
/music file 孤勇者         # 元の音声ファイルを添付
/music id:1901371647       # ID 指定で取得
/music search 陈奕迅       # 楽曲リストを検索
```

#### 取得できる情報

曲名、アーティスト、アルバム、カバー、音質（ビットレート／フォーマット／グレード）、ファイルサイズ、再生リンク。QQ プラットフォームでは再生リンクを自動で**ボイス（語音メッセージ）**に変換して送信します（フレームワークの `Record` メッセージセグメントに依存。非対応時はテキストリンクにフォールバック）。

> ⚠️ 一部の VIP 楽曲では再生リンクを取得できない場合があります。リンクには有効期限があるため、お早めにご利用ください。ボイス機能にはシステムの `ffmpeg` が必要です。

> 📦 **ファイルモードと大容量ファイル**：QQ／NapCat 環境では、`/音乐 文件` は OneBot ローカルアップロード（`upload_group_file` / `upload_private_file`）を優先します。これにより、`Comp.File` が誤った `callback_api_base` 経由で HTTP コールバックに変換され、再ダウンロードに失敗する問題（ログに「ファイルのダウンロード失敗」が出る）を回避できます。元の音声（特にロスレス flac）は非常に大きくなることがあり、ファイルが `music_file_max_bytes`（デフォルト 25MB）を超えると、送信前に自動で 128kbps MP3 へトランスコードします（`ffmpeg` 必要）。サイズは約90%減。ロスレスファイルをそのまま送りたい場合はこの閾値を引き上げられますが（非推奨。送信失敗しやすい）、ダウンロード側はタイムアウト／ネットワークエラー時に自動リトライします。

> 🚫 **連打防止**：短期間の連続リクエストによる大量の並行ダウンロード／トランスコードでサーバーがパンクするのを防ぐため、リクエストコマンドには「処理中の重複排除＋クールダウン」（`music_cooldown`、デフォルト3秒）が組み込まれています。前の曲の処理中に再度リクエストすると「しばらくお待ちください」、完了直後の再リクエストには「速すぎますよ！」と返します。別のグループ／DM には影響しません。

### 7. DG-LAB デバイス管理 (`/dglab`)

DG-LAB Socket プロトコル経由で DG-LAB パルスコントローラーを完全制御します。**[DG-LAB WebSocket 中継サーバー](https://github.com/dungeonlab-open/dglab-websocket-server)** の起動が必要です。

> 📡 **プロトコルバージョン**：公式中継リポジトリは v2 サーバーを削除し、現在は **v3**（`bun run v3`、デフォルトポート 9999）と **v4**（`bun run v4`、デフォルトポート 9998）のみ提供しています。v2.0.0 以降、プラグインは中継サーバーのプロトコル（V3 / V4。旧 V2 中継も互換）を**自動判定**します。設定変更なしでアップグレードするだけで使えます。`dglab_protocol` 設定で手動指定（`auto` / `v3` / `v4`）も可能です。
>
> - **V3**：QR コード形式は旧版と同じ。DG-LAB アプリ／DG-LAB 4 アプリのどちらでもスキャン可能。
> - **V4**：新フォーマットの QR コード（`dungeon-lab.cn/s/?v=1&action=socket&url=...`）を使用し、**DG-LAB 4 アプリ**でのスキャンが必要。強度制御は `device.op` タスクで送信され（絶対強度はアプリから報告された現在値との差分に変換。報告がない場合は一時強度タスクにフォールバック）。

#### 基本コマンド

| コマンド | 説明 |
| --- | --- |
| `/dglab bind [サーバーアドレス]` | 新規デバイスをバインド（アプリでスキャンする QR コードを生成。複数台の追加に対応） |
| `/dglab unbind [番号]` | デバイスのバインド解除（複数台時は番号必須） |
| `/dglab strength [番号] <A\|B> <0-200>` | チャンネル強度を設定（番号省略時は #1） |
| `/dglab up [番号] <A\|B> [ステップ]` | 強度を上げる（デフォルト +5） |
| `/dglab down [番号] <A\|B> [ステップ]` | 強度を下げる（デフォルト -5） |
| `/dglab shock [番号] <A\|B> [強度] [波形] [秒数]` | ショック開始 |
| `/dglab stop [番号] [A\|B]` | ショック停止（強度ゼロ＋波形クリア） |
| `/dglab pulse [番号] <A\|B> <プリセット\|HEX> [秒数]` | 波形データを送信（デフォルト5秒） |
| `/dglab clear [番号] <A\|B>` | 波形キューをクリア |
| `/dglab feedback [番号]` | リアルタイム強度とフィードバックボタン状態を表示 |
| `/dglab permission [on\|off]` | 権限分離の確認／切替（デフォルト オン） |
| `/dglab status` | 全デバイスのバインド・接続状態を表示 |
| `/dglab info` | 全デバイスの詳細情報を表示 |
| `/dglab help` | ヘルプ表示 |

> 💡 **複数デバイス**：1ユーザーが複数台をバインドでき、番号（1/2/3…）で区別します。省略時は #1。他人のデバイスを制御する例：`/dglab strength @ユーザーID 2 A 50`。

#### 波形プリセット

| プリセット | 効果 | プリセット | 効果 |
| --- | --- | --- | --- |
| `breathe` | ゆっくり膨らんで消える呼吸 | `needle` | 高頻度の連続ピリピリ |
| `pulse` | 速い間欠パルス | `throb` | 低頻度のゆったり波 |
| `wave` | 連続するさざ波 | `chaos` | 強弱ランダムの交互 |
| `tap` | 短い単発タップ | `heartbeat` | 二拍の心拍リズム |

#### 利用の流れ

```text
1. デバイスをバインド
   /dglab bind ws://192.168.1.100:9999
2. DG-LAB アプリで QR コードをスキャンしてバインド完了
3. デバイスを制御
   /dglab shock A 50 breathe 10   # Aチャンネル（強度50、呼吸波形、10秒）
   /dglab strength A 50           # Aチャンネルの強度のみ設定
   /dglab pulse A wave 5          # さざ波波形を5秒送信
   /dglab up B 10                 # Bチャンネル強度 +10
   /dglab stop                    # 全出力を停止
4. 状態確認
   /dglab status
   /dglab feedback
5. バインド解除（任意）
   /dglab unbind
```

#### CCDG WebUI コントロールパネル

`dglab_webui_enabled` を有効にすると、プラグインは `dglab_webui_host`:`dglab_webui_port`（デフォルト `127.0.0.1:9178`）で CCDG WebUI ブラウザリモート制御インターフェースを起動します。ブラウザからデバイスの閲覧・制御が可能で、Material Design 3 スタイルです。

> ⚠️ **CCDG WebUI のセキュリティ（重要）**
> - v1.5.3 以降、**WebUI はデフォルトで無効**（`dglab_webui_enabled` は `false`）で、手動での有効化が必要です。
> - デフォルトのリッスンアドレスは `127.0.0.1`（ローカルアクセスのみ）。**公開する場合は `dglab_webui_host` を明示的に `0.0.0.0` に設定し、必ずリバースプロキシとアクセス制御（Nginx + Basic Auth／IP ホワイトリストなど）を前置してください**。
> - **総合 Pages → DG-LAB 制御** の「公開トグル」で `127.0.0.1` / `0.0.0.0` をワンクリック切替することもできます（確認ダイアログと公開リンク表示付き。オンにすると ufw でポートを自動許可、オフ／WebUI 無効化で自動的に取り消し）。
> - WebUI は独自のユーザー登録／ログインシステムを持ち、**ボット本体やプラットフォームアカウントとは無関係**です。そのポートに到達できる人は誰でもアカウントを登録できます。無防備なまま公開しないでください。
> - 推奨はローカルでの利用、または LAN 内／認証付きリバースプロキシ経由の公開のみです。

#### 高度な特徴

- **マルチユーザー分離**：ユーザーごとに独立した接続とバインドを持ち、最大50の同時接続に対応。
- **自動再接続**：処理失敗時に自動リトライ（最大2回）。切断時は再構築を試み、5分間アイドルで自動クリーンアップ。
- **安全機構**：全パラメータを厳格に検証し、処理はタイムアウト保護、強度は 0-200 に制限。

> ⚠️ 対応しているのは **DG-LAB（Coyote）3.0 パルスコントローラー**のみです。QR コードはセッション中有効で、期限切れ後は再生成が必要です。LAN では `ws://`、公開環境では `wss://` を推奨します。

#### DG-LAB 制御：公開トグル

- **WebUI マスタースイッチ**：CCDG WebUI のみを有効化。リッスンは `127.0.0.1` のまま（ローカルのみ。**公開とはみなされません**）。
- **公開トグル**（先に WebUI の有効化が必要）：オンにすると `dglab_webui_host` を `0.0.0.0`（ポート `dglab_webui_port`、デフォルト `9178`）へ切り替え、サーバーの公開 IP を検出して公開リンクを表示。オフにすると自動で `127.0.0.1` に戻ります。
- 公開時には**確認ダイアログ**が表示され、セキュリティ警告が常時表示されます。WebUI マスタースイッチをオフにした際もリッスンアドレスは自動で `127.0.0.1` に戻り、公開設定が残留しません。

> ⚠️ **セキュリティに関する注意**：`0.0.0.0` でリッスンすると、インターネット上の任意のアドレスから WebUI の登録／ログイン／デバイス API に到達できます。公開する前に必ず**リバースプロキシ＋認証**（Caddy + BasicAuth、Nginx + IP ホワイトリスト、Cloudflare Zero Trust など）を設定してください。さもないと、誰もがあなたの DG-LAB デバイスを制御できる状態になりかねません。

#### DG-LAB 制御：中継サーバーのワンクリックデプロイ（v3/v4）

DG-LAB 制御ページでは、公式 v3 / v4 中継サーバー（[dglab-websocket-server](https://github.com/dungeonlab-open/dglab-websocket-server)、Bun ランタイム）をサーバー上に**ワンクリックでデプロイ**できます。コマンドライン操作は不要です：

- **自動検出**：v3（ポート 9999）と v4（ポート 9998）をそれぞれ独立して検出・管理。デプロイ済みの場合は稼働状態、systemd サービス名、ソースバージョンを表示し、ワンクリックでアンインストールも可能（手動デプロイされた既存サービスも認識して引き継ぎます）
- **ワンクリックデプロイ**：Bun インストール → 公式リポジトリのクローン → 設定書き込み → 依存関係インストール → systemd 常駐サービス作成（起動時自動開始、クラッシュ時自動再起動）→ プロトコル自己チェックまで自動。全体で約10〜60秒
- **公開トグル**（デフォルト オフ）：公式サーバーは常に全インターフェースでリッスンするため、「ローカル／公開」の到達性はファイアウォールで制御します——オフの間はポートがブロックされ（ローカルの `ws://127.0.0.1:ポート` のみ到達可能、ページにはローカルアドレスを表示）、オンにするとポートを ufw で自動許可し、公開アドレス `ws://公開IP:ポート` を検出・表示。オフにすると自動的に取り消します。許可の前に確認ダイアログがあります
- **アンインストール**：systemd サービスの停止・削除とファイアウォール許可の取り消し。ソースディレクトリは残るため、再デプロイは数秒で完了

> ⚠️ **セキュリティに関する注意**：中継ポートを開放すると、アドレスを入手した DG-LAB アプリなら誰でもその中継に接続できます。利用中のみ有効にし、使い終わったらオフにするのがおすすめです。デプロイ／アンインストールには systemd と ufw が必要です（AstrBot の root 実行が必要）。

## 🧩 グループ別スイッチ

グループごとに本プラグインの有効／無効を独立して制御でき、他に影響しません。例えば、あるグループで画像／リクエスト機能が不要なら、そのグループだけオフにできます。

#### 基本コマンド

| コマンド | 説明 |
| --- | --- |
| `/开关 off` | このグループでプラグインの全コマンドを**恒久的に無効化**（pixiv／解析／music／… すべて反応しなくなる） |
| `/开关 off <期間>` | **時間指定で無効化**し、期間満了後に自動復帰。例：`/开关 off 2h`、`/开关 off 30m`、`/开关 off 2小时30分钟` |
| `/开关 off <ドメイン> [期間]` | **特定の機能カテゴリだけ無効化**。例：`/开关 off media 2h` はメディア解析だけ 2 時間オフ |
| `/开关 on` | このグループでプラグインのコマンドを**再有効化**（時間指定オフの早期解除も可） |
| `/开关 on <ドメイン>` | 特定カテゴリだけ再有効化。例：`/开关 on media` |
| `/开关 status [ドメイン]` | このグループの現在の状態を表示（時間指定オフは復帰予想時刻を表示） |
| `/开关列表`（`/switch_list` `/开关状态列表`） | **管理者**：このプラットフォームで無効化された全グループ（ドメイン含む）と復帰時刻を一覧表示 |
| `/开关` | 引数なし = 状態表示＋使い方のヒント |

> エイリアス：`/toggle`、`/switch`（例：`/toggle off 2h`）。中国語コマンド `/开关` は `关`（オフ）／`开`（オン）／`状态`（状態）も引数に取れます。期間の単位：`s`/`秒`、`m`/`分`/`分钟`、`h`/`时`/`小时`、`d`/`天`（組み合わせ可）。
>
> **機能ドメイン**（省略可。省略時 = グローバル全コマンド）：`media` メディア解析 · `image` 画像取得 · `music` 楽曲リクエスト · `utility` 実用ツール · `dglab` DG-LAB デバイス · `memory` グループ横断メモリ。中国語名も使用可（例：`/开关 off 图片`）。

#### 使用例

```text
/开关 off       # このグループで CurrentCortex の全コマンドを恒久的にオフ
/开关 off 10h   # 10時間だけオフ（夜間の迷惑防止など、満了で自動復帰）
/开关 off media 2h   # メディア解析だけ 2 時間オフ、リクエスト／画像は影響なし
/开关 status media   # メディアドメインの状態（⏳ 1時間58分後に自動復帰）
/开关列表       # 管理者：このプラットフォームの無効化グループとドメインの一覧
/开关 on media  # メディア解析だけ再有効化
/开关 on        # 再有効化（恒久・時間指定のどちらにも有効）
```

#### 仕組みと補足

- **状態の永続化**：スイッチの状態は `data/currentcortex_group_switch.json` に保存され、再起動後も保持されます。デフォルト（未設定）は**有効**で、`/开关 off` したグループだけが無効になります。
- **ドメイン別スイッチ（scope）**：保存キーは `umo`（グローバル）または `umo|ドメイン`（ドメイン別）。グローバル無効はどのドメイン状態より優先されます。旧データ（純粋な `umo` キー）はグローバル無効とみなされ、移行は不要です。
- **時間指定の自動復帰**：`/开关 off [ドメイン] <期間>` は満了後に自動で有効に戻ります（遅延満了判定のためバックグラウンドタイマー不要）。再起動後もカウントダウンは有効です。
- **無効化中の一回だけヒント**：無効化後、対象コマンドの初回使用時に短いヒントを返し（「このグループではメディア解析だけ無効です」など）、同一グループ同一カテゴリは 1 時間に 1 回のみ。`group_switch_hint_enable` でオフにできます。
- **デッドロックなし**：`/开关` と `/开关列表` コマンド自体は**常に使用可能**——無効化されたグループでも `/开关 on` で再有効化でき、阻止されることはありません。
- **権限**：デフォルトでは**グループ管理者**（フレームワークが識別する admin）のみ操作可能です。管理者として認識されない場合は、設定で `group_switch_admin_only` をオフにしてください。`/开关列表` は常に管理者専用です。
- **本プラグインのみに作用**：このスイッチは CurrentCortex のコマンドだけを遮断し、AstrBot の他プラグインやボット本体の機能には影響しません。
- **⚠️ LLM ツールはドメインスイッチの対象外**：ドメインスイッチはユーザーコマンドのみを制約します。LLM ツール経由で AI が自律呼び出しする画像／リクエスト／DG-LAB 等はコマンド入口を通らないため、ドメイン別オフの影響を受けません（グローバルオフは引き続き遮断します）。気になる場合は `llm_tools_enable` もオフにしてください。
- **DM は対象外**：スイッチはグループチャットのみ有効です。

| 設定項目 | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `group_switch_enable` | bool | true | グループ別スイッチ機能の有効化（オフの場合、ガードは一切動作しません） |
| `group_switch_admin_only` | bool | true | `/开关` を操作できるのをグループ管理者のみに制限 |
| `group_switch_hint_enable` | bool | true | 無効化中に対象コマンド初回使用時に一回だけヒントを返す（同一グループ同一カテゴリ 1 時間に 1 回） |

## ✂️ 分割返信

オプション機能：ボットの返信を**複数メッセージに分割して順次送信**し、「逐次返信」のリズムを再現して、長い返信をより自然で人間らしくします。デフォルトはオフで、設定パネルから手動で有効にしてください。

#### 動作方式

有効にすると、プラグインは返信の送信前に介入し、選択したルールでテキスト全体をいくつかに分割し、1つずつ送信します。各段の間にはランダムな遅延を挟みます（最初の段は遅延なし）。

> ⚠️ **フレームワーク標準機能との関係**：AstrBot 自体にグローバルの「分割返信」機能（`プラットフォーム設定 → 分割返信`）があります。**本プラグインの機能はそれと独立しており、同時に有効にしないでください**。両方オンにすると二重に分割されます。どちらか一方で十分です——フレームワーク側で有効にしている場合は、こちらはオンにしないでください。

#### 設定項目

| 設定項目 | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `reply_seg_enable` | bool | false | **【マスタースイッチ】** 分割返信の有効化 |
| `reply_seg_only_llm` | bool | true | LLM（大モデル）の返信のみ分割。オフにするとプラグインのコマンド返信（`/pixiv` など）も分割されます。オン推奨 |
| `reply_seg_mention` | bool | true | 分割返信の最初のメッセージでユーザーにメンション＋返信引用をするか（複数段の帰属を明確に）。引用返信非対応のプラットフォームでは自動的にフォールバック |
| `reply_seg_mode` | string | llm | 分割モード（ドロップダウン）：`llm`=LLM セマンティック分割（デフォルト・推奨、最もスマート）、`punct`=句読点分割（最軽量）、`length`=長さ分割（下記参照） |
| `reply_seg_llm_provider_id` | string | `""` | **llm モード専用**：分割に使う LLM プロバイダー ID。空の場合は現在の会話のモデルを再利用。安価で高速なモデルを推奨 |
| `reply_seg_llm_density` | string | `medium` | **llm モード専用**：分割密度（各段の目標文字数）。`low`=長め（約40-70字、分割少ない）、`medium`=標準（約20-45字）、`high`=短め（約10-25字、こまかく元気よく）。段数上限は自動で算出されプロンプトに反映 |
| `reply_seg_llm_max_segments` | int | `0` | **llm モード専用**：段数の上限。`0`=密度レベルから自動算出（low=3／medium=5／high=8）。手動でハード上限を指定すると、超過分は最終段に統合 |
| `reply_seg_llm_min_chars` | int | 30 | **llm モード専用**：この文字数未満のテキストは LLM を呼ばずそのまま送信（推奨 20〜50） |
| `reply_seg_llm_timeout` | int | 30 | **llm モード専用**：1回の呼び出しタイムアウト秒数。超過時はルール分割にフォールバック。デフォルト30秒は大半のモデル（推論モデル含む）をカバー |
| `reply_seg_split_symbols` | string | `。！？!?~～…`＋改行＋`,，` | punct/length モード：1文字の区切り記号（この記号で分割し、記号は段末に残る）。デフォルトで中英コンマを含む |
| `reply_seg_split_words` | string | `喵 qwq owo awa ovo` | punct/length モード：区切り語（複数文字可、**スペース区切り**）。語の後ろで分割し、語は段末に残る。⚠️ 複数文字の語のみ推奨：1文字の語（`w` など）は英単語を誤分割し、左括弧 `（` はペアを壊すため、どちらもデフォルトでは含まれません |
| `reply_seg_merge_threshold` | int | 4 | punct モード：短い段の統合しきい値。この長さ未満の段は前の段に統合され、**純粋な記号段（孤立した「。」など）は無条件で統合**——コンマの断片や孤立記号を解消。`0` で統合を無効化 |
| `reply_seg_min_length` | int | 15 | length モード：最小段長。これ未満では分割しない（推奨 10〜30） |
| `reply_seg_max_length` | int | 80 | length モード：最大段長。超過時は `[最小, 最大]` の範囲で区切り点（記号・語）を逆方向に探し、見つからない場合のみハード分割（推奨 50〜150） |
| `reply_seg_delay_range` | string | `0.8,2.5` | 段間のランダム遅延範囲（秒）。形式 `min,max` |

#### 3つの分割モード

- **`punct`（句読点）**：各区切り記号・語の位置で分割。最も軽量で、大半の会話に適します。分割後、**極端に短い段や純粋な記号段（孤立した「。」など）は前の段に自動統合**され、断片化を防ぎます（`reply_seg_merge_threshold` で制御、無効化も可能）。
- **`length`（長さ）**：ある段が最大段長を超えるとき、`[最小段長, 最大段長]` の範囲で分割点（記号・語）を逆方向に探して分割し、見つからない場合のみハード分割します。各段の長さを抑えたい場合に。
- **`llm`（LLM セマンティック分割）** ⭐推奨：LLM を呼び出して**意味の完全性**ベースで分割します。人が「一文ずつ話す」ように——コンマで細切れにせず、顔文字の帰属を保ち、リストや対比構造はトピックごとにまとめます。ルール式よりスマートな一方、返信ごとに**LLM 呼び出しが1回増え**、1〜3秒の遅延と少額のトークン消費が発生。短い返信（`reply_seg_llm_min_chars` 未満）は自動的にスキップされます。`reply_seg_llm_density` で低／中／高の3段階の密度を選べ、各段の文字数の規模を調整できます。

> 💡 **`llm` モードのコツ**：`reply_seg_llm_provider_id` には**安価で高速なモデル**（例：deepseek-v3）のプロバイダー ID を設定し、主モデルに負担をかけないようにしましょう。プロバイダー未設定の場合は現在の会話のモデルを再利用します。呼び出し失敗・解析異常・文字数の大幅なズレの際は**自動で** punct ルール分割にフォールバックし、通常の返信には影響しません。
>
> 💡 **分割密度**（`reply_seg_llm_density`）：`low`=長め（約40-70字、情報量重視・分割少なめ）、`medium`=標準（約20-45字）、`high`=短く細かく（約10-25字、チャット勢い重視）。レベルごとに段数上限が自動で算出されプロンプトに書き込まれます。段数を厳密に制御したい場合は `reply_seg_llm_max_segments` でハード上限を指定してください。

> 💡 `punct` / `length` モードでは、句読点に加えて**区切り語**（`reply_seg_split_words`、スペース区切り）を設定でき、`喵`、`qwq`、`owo` などの顔文字・語気詞の後ろで分割できます。両モードとも区切り記号と区切り語を同時に認識します。

#### 補足

- 分割後の完全な返信は会話履歴に正しく書き戻されるため、文脈の連続性は保たれます。
- 分割は**プレーンテキスト**の返信のみ対象。画像やファイルなどは分割されません。
- 分割処理で異常が発生した場合は、自動的に1通送信へフォールバックします（通常の利用には影響しません）。

## 🤖 LLM ツール

オプション機能：プラグインの画像取得・楽曲リクエスト・ショック制御などを**大モデルが呼び出せるツール（function calling）として登録**し、「猫耳の絵ちょうだい」「晴天を流して」「Aチャンネルの強度50にして」のような**自然言語リクエスト**を AI が自律処理できるようにします——`/` コマンドの入力は不要で、AI が意図を判断して対応するツールを呼び出します。デフォルトで有効。不要な場合は設定パネルの `llm_tools_enable` でオフにできます。

> ⚠️ ショック制御は物理デバイスを操作し、安全上のリスクを伴います。安全を確認したうえで有効にしてください。すべてのツールは実行の最初でマスタースイッチを確認し、オフの場合は実行せずメッセージを返します。

#### 登録されるツール一覧（全11個）

| 分類 | ツール名 | パラメータ | 説明 |
| --- | --- | --- | --- |
| 🖼️ 画像 | `get_pixiv_random` | num, r18 | ランダムな二次元イラスト |
| 🖼️ 画像 | `search_pixiv` | keyword, num, r18 | キーワードでイラスト検索 |
| 🖼️ 画像 | `get_pixiv_by_tags` | tags, num, r18 | タグで精密絞り込み（複数タグ AND） |
| 👗 男の娘 | `get_femboy_image` | なし | ランダムな男の娘画像 |
| 🎵 リクエスト | `play_song` | song_name | 検索してリクエスト（ボイス） |
| ⚡ ショック | `dglab_shock` | channel, strength, wave, duration, device_index | ショック開始 |
| ⚡ ショック | `dglab_strength` | channel, value, device_index | 絶対強度を設定 |
| ⚡ ショック | `dglab_strength_adjust` | channel, direction, step, device_index | 強度を増減 |
| ⚡ ショック | `dglab_pulse` | channel, wave, duration, device_index | 波形を送信 |
| ⚡ ショック | `dglab_stop` | channel, device_index | 出力停止 |
| ⚡ ショック | `dglab_status` | なし | デバイス状態を照会 |

#### 動作方式

- **ゼロ再実装**：ツール内部は既存のビジネスロジックを完全に再利用（画像は `_process_response`、リクエストは `_search_and_get`、ショックは `_dispatch_command`）。車輪の再発明はしません。
- **メディア受け渡し**：画像／リクエスト／男の娘ツールは内部で `event.send` によりメディアを直接送信し、AI には一言の説明（「2枚の画像を送信しました」など）を `return` します。AI が同じ内容をテキストで繰り返さないようにするためです。
- **ショックの安全性**：ショックツールは AI が渡した構造化パラメータをコマンド文字列に組み立て直して `_dispatch_command` 経由で実行し、**権限検証・ユーザー間分離・デバイス解決を完全に継承**します。強度は 0-200 にクランプされ、波形プリセットは既存ロジックで検証されます。
- **自動フォールバック**：API キー未設定やデバイス未接続などの状況では、エラーではなく親切なメッセージを返します。

#### 設定項目

| 設定項目 | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `llm_tools_enable` | bool | true | **【マスタースイッチ】** オンで全ツールを登録。オフの場合は効果なし（従来の `/` コマンドのみ） |

> 💡 有効にすると、AI はユーザーのメッセージからツール呼び出しの要否を自動判断します。例えば「萝莉の絵ちょうだい」なら `get_pixiv_random`、「晴天が聴きたい」なら `play_song`、「ちょっと電流を」と言われれば `dglab_shock`（ショックデバイスのバインド・接続済みが前提）を呼び出します。

## 🧠 グループ横断メモリ

オプション機能：同一プラットフォームインスタンス上のすべてのグループチャットで1つの**永続化**メモリを共有し、追加コンテキストとして LLM リクエストに注入します。ボットが異なるグループ間でも連続した文脈を持てるようになります。

- **保存**：`data/currentcortex_cross_group.json`。プラットフォームインスタンス（`platform_id`）ごとにバケット分けされ、再起動後も保持されます。
- **記録**：グループチャットの非コマンドメッセージは `[ニックネーム/HH:MM:SS]: テキスト` の形式でローリング追記されます（上限を超えると古い記録から自動トリム）。
- **注入**：グループメッセージが LLM リクエストをトリガーしたとき、同プラットフォームの他グループの直近の記録を `<system_reminder>` としてユーザーメッセージ部に注入します。`cross_group_max_age_hours` を設定するとその期間内の記録のみ注入され、静かなグループで古い話題が掘り返されなくなります。
- **LLM 要約（オプション）**：`cross_group_summary_enable` 有効時、注入件数がしきい値を超えると LLM で元記録を話題ダイジェスト（「最近 XX と YY の話題」）に圧縮してから注入します——トークン削減・重点への集中。失敗時（モデルなし／タイムアウト／空結果）は元記録注入へ自動低下し、同一メモリは 5 分間ダイジェストを再利用します。注意：返信経路に 1 回の LLM 呼び出し（最長 20 秒）が加わるため、安価で高速なモデルを推奨します。
- **スラッシュコマンドは記録しない**：コマンドメッセージはメモリに入りません。
- **キーワード削除**：管理者が `/忘记 <キーワード>`（エイリアス `/forget_memory` `/忘记记忆`）を送ると、このプラットフォームのメモリから当該キーワードを含む全記録を削除できます（部分一致・大文字小文字を区別しない）。誤記録のピンポイント削除に便利で、プラットフォーム全体のメモリを消す必要はありません。

| 設定項目 | デフォルト | 説明 |
| --- | --- | --- |
| `cross_group_enable` | false | グループ横断メモリの有効化 |
| `cross_group_max_cnt` | 500 | プラットフォームごとの最大記録件数 |
| `cross_group_inject_cnt` | 30 | 1回の返信で注入する直近記録件数 |
| `cross_group_max_age_hours` | 0 | LLM 注入時に直近 N 時間内の記録のみ対象（`0` = 期間制限なし、件数のみでトリム＝旧動作。12〜48 推奨） |
| `cross_group_summary_enable` | false | LLM 要約の有効化（注入件数がしきい値超過時に話題ダイジェストへ圧縮） |
| `cross_group_summary_threshold` | 20 | 要約を発動する注入件数のしきい値（未満は元記録を直接注入） |
| `cross_group_summary_provider_id` | （空） | 要約専用モデル ID。空なら現在のセッションモデルを再利用。安価で高速な非推論モデルを推奨 |

> ⚠️ 有効にすると他グループのチャット内容が LLM に提供されます。あなたのプライバシー期待と、各グループメンバーの知情同意に合致するか確認してください。

## ⚡ API 接続テスト (`/apitest`)

LeiZ 上流エンドポイント全部の認証・接続状態を一括診断し、「API 障害」なのか「コードの問題」なのかを切り分けます。

```text
/apitest          # 全6エンドポイントを並列 probe
/apitest help     # ヘルプ表示
```

5つのエンドポイント（Pixiv / Hitokoto / 天気 / 男の娘 / リクエスト）を並列にプローブし、各々には最も軽量な読み取り専用リクエストを使うため、画像／音声のダウンロード通信は消費しません。状態の意味：

| アイコン | 状態 | 意味 |
| --- | --- | --- |
| 🟢 | 正常 | エンドポイントが成功を返却 |
| 🟡 | HTTP 異常 | 200 以外の応答（401 認証失敗／402 クォータ／5xx など） |
| 🔴 | ネットワーク／タイムアウト | 接続失敗または設定タイムアウト超過 |
| ⚫ | スキップ | 対応クライアント未初期化（通常は API キー未設定） |

<details>
<summary><b>📦 DG-LAB 中継サーバーのデプロイ（Bun）</b></summary>

1. サーバーコードの入手：[dglab-websocket-server](https://github.com/dungeonlab-open/dglab-websocket-server)
2. [Bun](https://bun.sh) をインストール後、対応バージョンのサーバーを起動：
   ```bash
   bun run v3     # V3 サーバー、デフォルトポート 9999（旧アプリ互換）
   bun run v4     # V4 サーバー、デフォルトポート 9998（DG-LAB 4 アプリが必要）
   ```
3. ポートなどは `.env` で変更可能（`PORT` / `PREFIX` など。リポジトリの README を参照）
4. AstrBot と DG-LAB アプリの両方がそのサーバーへアクセスできることを確認。`/dglab bind` の際、プラグインはプロトコルバージョンを自動判定し、応答に明記します

</details>

<details>
<summary><b>❓ 接続トラブルシューティング（<a href="https://github.com/backrooms-yrc/astrbot_plugin_currentcortex/issues/3">issue #3</a> 対応）</b></summary>

- **`サーバーが接続を確認しない: サーバー割り当て clientId 待ちでタイムアウト`**：旧バージョン（≤ v1.9.1）は v2 プロトコルに従い接続パスに自己生成の clientId を含めており、v3 サーバーがアプリ側と誤認して拒否していました。v2.0.0 以降にアップグレードすれば解決します。v2.0.0 からは制御側がルートパスへ素の接続を行い、サーバー割り当ての clientId を使います。
- **`接続失敗: server rejected WebSocket connection: HTTP 404`**：v4 サーバーに余分なパス付きのアドレスで接続しています。v4 サーバーはルートパス（または `PREFIX` で設定したパス）でのみ接続を受け付けるため、`dglab_server_url` が実際のリッスンパスと一致しているか確認してください。
- **V4 でバインド後に制御が効かない**：**DG-LAB 4 アプリ**でのスキャンを確認してください（新フォーマット `dungeon-lab.cn/s/...` の QR コードは旧アプリでは読めません）。アプリ内に複数のデバイススロットがある場合、プラグインは実際に接続している最初のスロットを自動選択します。

</details>

<details>
<summary><b>🔄 旧版 DG-LAB JSON 設定からの移行</b></summary>

v1.2.0 以前は JSON 文字列の設定を使っていました（非推奨）：

```json
{ "dglab": { "server_url": "ws://your-server:9999", "heartbeat_interval": 60, "auto_connect": false } }
```

新形式は3つの独立項目です：`dglab_server_url`、`dglab_heartbeat_interval`、`dglab_auto_connect`。プラグインは旧 `dglab` JSON 設定も検出します。新項目が空で旧設定が存在する場合は自動で読み込み、移行を案内します。早めの手動移行をおすすめします。

</details>

## ❓ よくある質問

<details>
<summary><b>インストール後にプラグインが読み込まれない？</b></summary>

1. Python が 3.10 以上か
2. 依存関係はインストール済みか：`pip install aiohttp>=3.8.0`（DG-LAB にはさらに `websockets>=10.0`）
3. AstrBot が 4.15 以上か（本プラグインは比較的新しい API が必要で、旧版では読み込めません）
4. AstrBot ログのエラーメッセージを確認

</details>

<details>
<summary><b>コマンドを実行すると「機能が無効／API キー未設定」と出る？</b></summary>

まず [LeiZ API 公式サイト](https://api.bileizhen.top)で API キーを取得し（[API キー設定](#2-api-キー設定-必須) 参照）、設定パネルの `leiz_api_key` フィールドに入力して保存、プラグインを再読み込みしてください。`/apitest` で各エンドポイントの接続を検証できます。Pixiv／Hitokoto／天気／男の娘／リクエストはすべてこのキーに依存します。

</details>

<details>
<summary><b>Pixiv の画像が表示されない？</b></summary>

1. リバースプロキシのドメインが利用不可：`image_proxy` 設定を変更してみる
2. ネットワークの問題：サーバーが外部ネットワークへアクセスできるか確認
3. API サービスの異常：しばらく待って再試行

</details>

<details>
<summary><b>AI 生成された Pixiv 作品を除外するには？</b></summary>

1. **全体で除外**：`exclude_ai` を `true` に設定
2. **その場だけ除外**：コマンドに `excludeAI:true` を付ける（例：`/pixiv tag:萝莉 excludeAI:true`）

</details>

<details>
<summary><b>リクエストがタイムアウトする？</b></summary>

`request_timeout`（秒）を適度に引き上げ、ネットワーク状況を確認してください。頻発するタイムアウトは大抵 API 側の混雑なので、後ほど再試行をおすすめします。

</details>

<details>
<summary><b>天気照会の対応都市は？</b></summary>

中国の主要都市に対応しています。中国語の都市名（「广州市」「北京」など）を推奨。最大50文字です。

</details>

<details>
<summary><b>DG-LAB 機能が使えない／バインドに失敗する？</b></summary>

1. 依存関係はインストール済みか：`pip install websockets>=10.0`
2. `dglab_server_url` は設定済みか。中継サーバーが起動してアクセス可能か
3. QR コードは有効期限内にアプリでスキャンしたか
4. アプリが Socket V2 に対応していること、対応デバイスが **DG-LAB 3.0 パルスコントローラー**のみであることを確認
5. AstrBot ログの `[DGLab]` 関連エラーを確認

</details>

<details>
<summary><b>DG-LAB の接続が切れたら？</b></summary>

自動再接続します（最大2回）。それでも失敗する場合は `/dglab unbind` で解除してから `/dglab bind` をやり直し、`/dglab status` で状態を確認してください。

</details>

<details>
<summary><b>複数人が同時に使うと競合する？</b></summary>

しません。ユーザーごとに独立したデバイスバインドと接続を持ち、操作は完全に分離され、最大50の同時接続に対応します。

</details>

### エラー処理一覧

| エラー種別 | 考えられる原因 | 対処 |
| --- | --- | --- |
| ネットワークエラー | 接続失敗 | ネットワーク接続を確認 |
| リクエストタイムアウト | API 応答が遅い | `request_timeout` を引き上げるか後で再試行 |

| データ形式異常 | API が異常なデータを返却 | 後で再試行 |

### 設計の特徴

- **非同期アーキテクチャ**：`asyncio` + `aiohttp` / `websockets` によるノンブロッキング I/O
- **モジュール設計**：DG-LAB 機能を責務ごとに複数モジュールへ分離
- **統一インターフェース**：すべての API クライアントが同じ設計パターンに従う
- **堅牢な耐障害性**：網羅的な例外処理、パラメータ検証、必要に応じたリトライ
- **データの永続化**：DG-LAB のバインドは `data/dglab_bindings.json`、グループ横断メモリは `data/currentcortex_cross_group.json`（いずれも AstrBot 規範に準拠）
- **リソース管理**：接続プールがアイドル接続を自動整理し、リークを防止
- **マルチテナント分離**：ユーザーごとに独立した接続であり、操作が互いに干渉しない
